3×3 旋转矩阵：从零理解

前提：你已经理解了 2×2 的旋转矩阵。下面一步步把它扩展到三维。

1. 两个关键想法

想法一：3D 旋转 = 固定一根轴，在剩下的平面里做 2D 旋转。想象一扇门：门轴不动，门板在地面这个平面里转。绕 z 轴转的时候，z 方向的东西完全不变（高度不变），只有 x、y 在变，而 x、y 怎么变，就是你已经会的 2D 旋转：

绕 z 轴：
⎡ cosθ  −sinθ   0 ⎤    ← 左上角就是 2D 旋转矩阵
⎢ sinθ   cosθ   0 ⎥
⎣  0      0     1 ⎦    ← z 不动，所以是 1，其余补 0

绕 x 轴、绕 y 轴也是同一个模式，只是那个“2D 小方块”换到了别的位置：

绕 x 轴：                 绕 y 轴：
⎡ 1    0      0   ⎤      ⎡  cosθ  0  sinθ ⎤
⎢ 0  cosθ  −sinθ  ⎥      ⎢   0    1   0   ⎥
⎣ 0  sinθ   cosθ  ⎦      ⎣ −sinθ  0  cosθ ⎦

想法二：矩阵的每一列 = 一根坐标轴转完之后到了哪里。第 1 列是 x 轴转完后的新坐标，第 2 列对应 y，第 3 列对应 z。下面的动画里，矩阵每一列的颜色和对应箭头的颜色一致。

3. 为什么要拿矩阵去乘 (1, 0, 0)？

因为 (1, 0, 0) 就是 x 轴那根箭头本身。坐标 (1, 0, 0) 的意思是：往 x 方向走 1 步，y 方向 0 步，z 方向 0 步。从原点走到这个点，画出来的箭头正好沿着 x 轴，长度是 1（动画里橙色那根）。同样，(0, 1, 0) 是 y 轴箭头（绿色），(0, 0, 1) 是 z 轴箭头（紫色）。

所以“R × (1, 0, 0)”翻译成大白话就是：把 x 轴那根箭头转一下，看它跑到哪里去。

为什么只关心这三根箭头？因为空间里任何一个点都能用它们拼出来。比如点 (2, 3, 0) 就是“2 根 x 箭头 + 3 根 y 箭头”接在一起。旋转时整个空间像一块硬积木一起转，所以只要知道三根箭头各去了哪，任何点去哪都知道了。

以绕 z 轴转 90° 为例：新 x 箭头 = (0, 1, 0)，新 y 箭头 = (−1, 0, 0)，所以

(2, 3, 0) 转完 = 2×(0, 1, 0) + 3×(−1, 0, 0) = (−3, 2, 0)
把三根箭头转到哪里记下来，就相当于记住了整个旋转。矩阵的三列，存的正好就是这三条信息。上面动画最下面一行，就是对点 P 做的这个计算。

4. 为什么写进“列”而不是“行”？

因为矩阵乘向量的算法决定了：拿矩阵乘 (1, 0, 0)，结果正好是矩阵的第 1 列。规则是：结果的每个数 = 矩阵的一行和向量对应位置相乘再相加。

⎡ a  b  c ⎤   ⎡ 1 ⎤
⎢ d  e  f ⎥ × ⎢ 0 ⎥
⎣ g  h  i ⎦   ⎣ 0 ⎦

第 1 个数 = a×1 + b×0 + c×0 = a
第 2 个数 = d×1 + e×0 + f×0 = d
第 3 个数 = g×1 + h×0 + i×0 = g
结果 = (a, d, g) = 第 1 列

向量里的 1 在第一个位置，它“挑出”了每一行的第一个数，竖着排起来就是第 1 列。同理，乘 (0, 1, 0) 得到第 2 列，乘 (0, 0, 1) 得到第 3 列。

所以，想要“R × x 箭头 = x 箭头转完后的位置”，这个位置就必须放在第 1 列。验证一下绕 z 轴 90°：

⎡ 0  −1  0 ⎤   ⎡ 1 ⎤   ⎡ 0 ⎤
⎢ 1   0  0 ⎥ × ⎢ 0 ⎥ = ⎢ 1 ⎥   ← x 转到了 y ✓
⎣ 0   0  1 ⎦   ⎣ 0 ⎦   ⎣ 0 ⎦

如果错写成行，乘出来会是 (0, −1, 0)，方向就反了。这和 2D 一样：2D 旋转矩阵的第 1 列 (cosθ, sinθ) 就是 x 轴转了 θ 之后的位置。

5. 右手定则

在 3D 里光说“顺时针”不够，因为从轴的正面看和从背面看，顺逆时针刚好相反。所以大家统一用右手来规定方向：

伸出右手，大拇指指向旋转轴的正方向，其余四指握拳弯曲，四指弯曲的方向就是正角度的旋转方向。

拿绕 z 轴来说：大拇指朝上，四指从 x 弯向 y。从上往下看是逆时针，和 2D 里“正角度 = 逆时针”一致。

它也规定了坐标轴怎么摆：四指从 x 弯向 y，大拇指指的就是 z。这叫“右手坐标系”，数学、物理、机器人和大多数 3D 软件都用它。

6. 为什么绕 y 轴时 −sin 跑到了左下角？

不用记规则，直接算。下图把两种旋转都“压扁”成从轴的正上方看到的样子：

右图的轴不是随便摆的：站在 y 轴正上方往下看，真实空间里 z 就在右边、x 就在上边（可以在上面的动画里拖视角验证）。两张图是同一个动作，都是“逆时针转 90°”，差别只是绕 y 轴时排在“右边”的那根轴是 z 而不是 x。

用“每一列 = 那根轴转完后到了哪”来填矩阵，θ = 90°（cos = 0，sin = 1）：

绕 z 轴 90°：
  x → y  = (0, 1, 0)   写进第 1 列
  y → −x = (−1, 0, 0)  写进第 2 列
  z 不动 = (0, 0, 1)   写进第 3 列

⎡ 0  −1  0 ⎤      对照  ⎡ cos  −sin  0 ⎤
⎢ 1   0  0 ⎥            ⎢ sin   cos  0 ⎥     −sin 在右上
⎣ 0   0  1 ⎦            ⎣  0     0   1 ⎦
绕 y 轴 90°：
  x → −z = (0, 0, −1)  写进第 1 列
  y 不动 = (0, 1, 0)   写进第 2 列
  z → x  = (1, 0, 0)   写进第 3 列

⎡  0  0  1 ⎤      对照  ⎡  cos  0  sin ⎤
⎢  0  1  0 ⎥            ⎢   0   1   0  ⎥     −sin 在左下
⎣ −1  0  0 ⎦            ⎣ −sin  0  cos ⎦
没有特殊规则，−sin 的位置是算出来的：绕 y 轴转时，x 会被转到 −z（图中虚线），这个负号写进第 1 列，自然落在左下角。背后的原因是右手定则的循环顺序 x → y → z → x：绕 y 轴的正方向是“z 转向 x”，和矩阵按 x、y、z 书写的顺序刚好反过来。

7. 下一步

斜着转的复杂旋转，可以拆成“先绕 x 转、再绕 y 转、再绕 z 转”，把这几个矩阵乘起来就行。这正是机器人里描述姿态（欧拉角、RPY）的基础。
