第 4 步其实是把两件事一次做完了，这里拆成 5 小步。默认角度 θ₁ = 48°、θ₂ = 1°，可以拖滑块换别的角度。

用 θ₁ = 48°、θ₂ = 1° 的数字对一遍

一个比喻：T_AB 是“用 A 的话”写下的 B 的位置和朝向；T_WA 是一个翻译，把“A 的话”翻译成“世界的话”。两个矩阵相乘，就是让 T_WA 把 T_AB 的每一列都翻译一遍。

T_WA = ⎡ 0.67  −0.74  0.30 ⎤      T_AB = ⎡ 1.00  −0.02  2.20 ⎤
       ⎢ 0.74   0.67  0.30 ⎥             ⎢ 0.02   1.00  0.00 ⎥
       ⎣ 0.00   0.00  1.00 ⎦             ⎣ 0.00   0.00  1.00 ⎦

T_AB 的三列：
  第 1 列 (1.00, 0.02, 0)    B 的 x 轴，在 A 里朝哪
  第 2 列 (−0.02, 1.00, 0)   B 的 y 轴，在 A 里朝哪
  第 3 列 (2.20, 0.00, 1)    B 的原点，在 A 里的位置

用 T_WA 的每一行，分别去乘这三列：

第 3 列（B 的原点）：
  0.67×2.20 + (−0.74)×0.00 + 0.30×1 = 1.47 + 0 + 0.30 = 1.77
  0.74×2.20 +   0.67×0.00  + 0.30×1 = 1.63 + 0 + 0.30 = 1.93

第 1 列（B 的 x 轴）：
  0.67×1.00 + (−0.74)×0.02 + 0.30×0 = 0.67 − 0.01 + 0 = 0.66
  0.74×1.00 +   0.67×0.02  + 0.30×0 = 0.74 + 0.01 + 0 = 0.75

第 2 列（B 的 y 轴）：
  0.67×(−0.02) + (−0.74)×1.00 + 0.30×0 = −0.01 − 0.74 = −0.75
  0.74×(−0.02) +   0.67×1.00  + 0.30×0 = −0.01 + 0.67 =  0.66

按列放回去：
T_WB = ⎡ 0.66  −0.75  1.77 ⎤
       ⎢ 0.75   0.66  1.93 ⎥
       ⎣ 0.00   0.00  1.00 ⎦
注意每一列的第 3 个数：两根轴那两列是 0，原点那一列是 1。轴是方向，不应该加平移，0.30 × 0 把平移挡掉；原点是位置，需要加平移，0.30 × 1 把它加进来。这也是每个齐次变换矩阵最下面一行都是 0 0 1 的原因：前两列是方向（0），最后一列是位置（1）。

如果再加第 3 节手臂 C，就是 T_WC = T_WA × T_AB × T_BC，一层层翻译下去。6 轴机械臂就乘 6 个。

2. 为什么要补一个“1”？

旋转是乘法（R × p），平移是加法（+ t）。单靠 2×2 矩阵做乘法，没办法“加上一个固定的数”。补了 1 之后：

⎡ c  −s  tx ⎤   ⎡ px ⎤   ⎡ c·px − s·py + tx·1 ⎤
⎢ s   c  ty ⎥ × ⎢ py ⎥ = ⎢ s·px + c·py + ty·1 ⎥
⎣ 0   0   1 ⎦   ⎣  1 ⎦   ⎣         1          ⎦

第 1 行：cosθ×px − sinθ×py  +  tx×1
        └──── 这是旋转 ────┘   └ 这是平移

用数字一行一行算

物体不转（θ = 0），只往右移 3、往上移 2，t = (3, 2)。点 p = (1, 0.5)，补 1 写成 (1, 0.5, 1)。规则：矩阵的一行和向量对应位置相乘，再加起来。

T = ⎡ 1  0  3 ⎤
    ⎢ 0  1  2 ⎥
    ⎣ 0  0  1 ⎦

第 1 行 (1, 0, 3) 和 (1, 0.5, 1)：  1×1 + 0×0.5 + 3×1 = 1 + 0 + 3 = 4
第 2 行 (0, 1, 2) 和 (1, 0.5, 1)：  0×1 + 1×0.5 + 2×1 = 0 + 0.5 + 2 = 2.5
第 3 行 (0, 0, 1) 和 (1, 0.5, 1)：  0 + 0 + 1×1 = 1

结果 (4, 2.5, 1)  →  去掉最后的 1  →  P 的新位置 (4, 2.5)

4   = 1   + 3      原来的 x  +  往右移的 3
2.5 = 0.5 + 2      原来的 y  +  往上移的 2

每一行的最后一项是 3×1 和 2×1：因为乘的是 1，3 和 2 原封不动地成了加法里的一项，等于“加了 3”和“加了 2”。

如果没有这个 1

只用 2×2 矩阵，每一行只有“某数×px + 某数×py”两项，没有任何一项是单独加上的固定数。比如原点 (0, 0) 乘任何 2×2 矩阵都还是 (0, 0)，根本移不动。补上的 1 就像在向量里多开了一个格子，专门装“要加上的固定数”。

3. 为什么最下面一行是 0 0 1？

原因一：要有第 3 行，矩阵才是方的，才能串起来乘

去掉最下面一行，矩阵只剩 2×3，乘 (1, 0.5, 1) 只得到两个数 (4, 2.5)，那个 1 就丢了，下一个矩阵没法再加平移；而且两个 2×3 矩阵也乘不到一起（前一个的列数要等于后一个的行数）。

原因二：必须是 0 0 1，结果的第 3 个数才刚好还是 1

第 3 个结果数 = 0×px + 0×py + 1×1 = 1

前两个 0 挡掉 px、py，最后的 1×1 留下 1。不管点在哪，第 3 个数永远是 1。

换成别的数就会出错。比如写成 0 0 2：

第一次：(1, 0.5, 1) 右移 3、上移 2
第 3 个数 = 0×1 + 0×0.5 + 2×1 = 2     ← 结果变成 (4, 2.5, 2)，不再是 1

第二次：再左移 1、上移 1
x = 1×4 + 0×2.5 + (−1)×2 = 2         ← 应该是 3
y = 0×4 + 1×2.5 +   1×2  = 4.5       ← 应该是 3.5

第 3 个数变成 2，第二次的平移被乘了 2 倍，移多了。写成 1 0 1 的话，第 3 个数会变成 px + 1，跟着点的位置变，后面全乱。

保留 1 才能一直串下去

⎡ 1  0  −1 ⎤   ⎡ 4   ⎤   ⎡ 1×4 + 0×2.5 + (−1)×1 ⎤   ⎡ 3   ⎤
⎢ 0  1   1 ⎥ × ⎢ 2.5 ⎥ = ⎢ 0×4 + 1×2.5 +   1×1  ⎥ = ⎢ 3.5 ⎥
⎣ 0  0   1 ⎦   ⎣ 1   ⎦   ⎣ 0   +   0   +   1×1  ⎦   ⎣ 1   ⎦
整个流程：① 补 1，(1, 0.5) → (1, 0.5, 1)；② 乘矩阵，乘几个都行，1 会一直保留；③ 去掉 1，取前面的数作为最终坐标。最下面那行 0 0 1 就是负责让这个 1 一直保留的“保持器”。

4. 这个矩阵怎么“读”？

还是老办法：每一列 = 什么东西到了哪里。

  • 第 1 列 = 物体自己的 x 轴在世界里朝哪
  • 第 2 列 = 物体自己的 y 轴在世界里朝哪
  • 第 3 列 = 物体坐标系的原点在世界里的位置

所以：左上角读姿态，最右一列读位置。

例子：朝向 −180° 时，旋转部分为什么是 (−1 0 / 0 −1)？

要竖着按列读：

        第1列  第2列
       ⎡ −1     0 ⎤        第 1 列 (−1, 0) = (cos θ, sin θ)：x 轴转完朝左
       ⎣  0    −1 ⎦        第 2 列 (0, −1) = (−sin θ, cos θ)：y 轴转完朝下

⎡ cos θ   −sin θ ⎤      cos 出现两次（左上、右下），sin 也出现两次
⎣ sin θ    cos θ ⎦      所以 −1 出现两次、0 出现两次

乘以 (1, 0.5)：

⎡ −1   0 ⎤   ⎡ 1   ⎤   ⎡ −1×1 + 0×0.5    ⎤   ⎡ −1   ⎤
⎣  0  −1 ⎦ × ⎣ 0.5 ⎦ = ⎣  0×1 + (−1)×0.5 ⎦ = ⎣ −0.5 ⎦

用列的想法：1 × (−1, 0) + 0.5 × (0, −1) = (−1, −0.5)

转 180° 就是把点“掉头”到对面，两个坐标都变号。最后再加上物体的位置 t。

5. 搬到 3D：4×4 矩阵

⎡ r11  r12  r13  tx ⎤
⎢ r21  r22  r23  ty ⎥     左上 3×3：3D 旋转矩阵（姿态）
⎢ r31  r32  r33  tz ⎥     右边一列：位置 (tx, ty, tz)
⎣  0    0    0    1 ⎦     最下一行：固定是 0 0 0 1

点写成 (px, py, pz, 1)，乘法和串联的规则都不变。

6. 和正向运动学的关系

动画第 4 步已经是正向运动学了：给每一节手臂写一个齐次变换矩阵，按顺序乘起来，就得到末端的位姿。真实机械臂有 6 节，就是乘 6 个矩阵。下一步要学的 DH 参数，就是一套“怎么给每一节写这个矩阵”的标准规则。
